# Theming the UI Kit

The UI Kit is shipped with a default `jar` theme that must be imported and present in the SCSS load path.

## Built-in theme variants

A theme comes initially with no variant (light by default, with values given at build time), but can be switched at runtime.

To do so, import the theme variant:

```scss
@import '@la-jarre-a-son/ui/lib/theme/jar/light.scss';
@import '@la-jarre-a-son/ui/lib/theme/jar/dark.scss';
```

or in Typescript:

```ts
import '@la-jarre-a-son/ui/lib/theme/jar/light.scss';
import '@la-jarre-a-son/ui/lib/theme/jar/dark.scss';
```

### Provide className to body

Use the `ThemeProvider` component to change dynamically the className used on the `<body>`:

For instance, in your `App.tsx`:

```tsx
import React, { useState } from 'react';
import { ThemeProvider } from '@la-jarre-a-son/ui/lib/theme';

const THEME_NAME = 'jar';

function App() {
    const [theme, setTheme] = useState(localStorage.getItem('theme') || 'light');
    const toggleTheme = (dark: boolean) => {
        const t = dark ? 'dark' : 'light';
        localStorage.setItem('theme', t);
        setTheme(t);
    };

    return (
        <ThemeProvider theme={THEME_NAME} variant={theme}>
            {/*
            Your App Content
            */}
        </ThemeProvider>
    );
}
```

_NOTE: by default, the theme className is `theme-${themeName} theme-${themeName}--${themeVariant}` but you can override it via SCSS when importing it by defining the `$Theme--light_selector` or `$Theme--dark_selector` variable. If you do not provide the `variant` prop, only the `theme` prop will be used as `theme-${themeName}`._

## Override theme

Starting from a working Theme, you can then override any element in SCSS at build time, or in CSS at run time.

### SCSS: Override at build time

If you imported the UI Kit theme in your own files (i.e. load path containing files like `variables.scss`, `mixins.scss`, `typography.scss`), you can override any SCSS variables.

For instance, in `my-directory/variables.scss`:

```scss
@import '@la-jarre-a-son/ui/lib/theme/jar/variables';

$Button_backgroundColor: red; // will override the Button background at build time
```

You can have the complete list of overrideable SCSS variables for each component in the _Theming_ section of the Docs, (e.g. [Button Theming](/docs/components-button--docs#theming)).

### CSS: Override at run time

You can also define [CSS custom properties](https://developer.mozilla.org/docs/Web/CSS/Using_CSS_custom_properties) to override components styles, by adding a class to it, or redefine it in a parent.

For instance, if you create a `CustomButton` component that uses `Button`, you can change the button style in a `CustomButton.scss` like so:

```scss
.CustomButton {
    --Button_backgroundColor: red; // Any button with this CustomButton class will have a custom background.
}

.CustomContainer {
    --Button_backgroundColor: red; // Any button inside this CustomContainer will also have the custom background
}
```

You can have the complete list of overrideable CSS variables for each component in the _Theming_ section of the Docs, (e.g. [Button Theming](/docs/components-button--docs#theming)).

_NOTE: depending on the props you have used with the component, and the order of the SCSS imports, you may need a more selective CSS selector, or try to not define the props that would add additional styles_.
